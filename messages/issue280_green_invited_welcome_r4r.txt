## Changes

Eligible sponsored users get a centered “You have been invited!” dialog on
each fresh page entry; a browser reload does not reopen it. The dialog starts
with “Welcome to SIGMA.” followed by one of 100 distinct curiosity/research-
themed lines in normal body text. The allowance copy uses the effective
allowance for the signed-in account when it is $1.00 or less. A new account
gets “We will start you off with a $X.XX allowance.”; accounts with usage or
holds get “We added a $X.XX allowance to your account.” Escape and the
acknowledgment button dismiss it for that page visit. The invitation
acknowledgment remains persisted server-side. A database migration gives
existing accounts a default of no pending invitation welcome. Browser state
does not carry allowance across account switches.

The sponsored pill is retained in all header render paths. For an eligible
local sponsor, activating it starts the personal ChatGPT connection flow even
if a personal connection already exists; it does not disconnect that account.

While a research session is running, its outcome badge shows a 50-word maximum
summary of the current action and research focus, refreshed with session
updates. When neither field is available, the original “Pending · provisional”
label remains. Reopening a project from Home by clicking its project title
automatically expands and scrolls the Sessions pane to the active running
session.

The existing force-sponsored-mode flag configuration and rollback procedure
are documented in `docs/CLOUD_DEPLOYMENT.md` (section “Hosted sponsored-mode
selection”): the flag defaults off, only applies alongside sponsored access,
and rollback sets it to false followed by the guarded release/start procedure.
Production configuration was not changed and the flag was not enabled.

The home header places **Invite me!** directly under About. For account
testing, the action is temporarily visible to any account with hosted sign-in
enabled, including signed-in members, so it can open Google's account chooser
from an existing session. The request endpoint still requires a verified,
server-issued denied-login cookie before recording a request. A Google challenge
started from that action carries server-bound invite intent; after verified
sign-in for an uninvited identity, the client posts the request to the existing
server-verified invitation endpoint. Success dismisses the dialog and removes
Invite me. Delivery errors open the request dialog with a retry path. The
request dialog's underlined, transparent Close follows its title; Privacy
Notice is at lower left. Closing that notice returns to the invitation dialog,
and the About link returns to About. Both locations display **Privacy Notice**.
The sign-in pill's lower gap is 2.5 times the upper gap. Failed invitation
requests show one error and a standard **Try again** pill; a successful retry
closes the dialog and removes Invite me.
Administrator Settings now offers **Add** beside invitation requests. It adds
the verified email as a member using the configured default allowance and
changes the action to **Added** for an active email rule. The request table
omits Status and gives the verified-account column one third more width. The
Authorized users table collapses case/trailing-dot duplicates and shows the
most recently updated rule, preferring normalized spelling when timestamps tie.
The live notice now describes identity/access state, session cookies,
invitation and feedback records, per-account workspace content, sponsored
accounting, provider/mail sharing, and the current retention controls. It
remains version 1.0. The home artwork credit reads “Crafted by Brian Kramer”
and “and [a randomly selected adjective] OpenAI agents.” The adjective is
selected from the user's supplied list once per page load.
