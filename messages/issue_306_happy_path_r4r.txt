RED — R4R handoff: Issue #306 and happy-path reliability (#302)

## SECTION A — ISSUE #306

### Terminology changes

- “Skeptic iterations” is now “Research rounds”: one round is one
  Investigator→Skeptic exchange per strategy.
- “Maximum agent calls” is now “Maximum agent turns”: one turn is one provider
  call by either role, shared across all selected strategies.
- Progress, session metrics, summaries, and saved artifact labels use rounds
  and agent turns consistently.

### Defaults and rationale

- Research rounds: 2 (per-strategy ceiling).
- Maximum agent turns: 12 (shared ceiling; six full pairs in the one-strategy
  case).
- Duration: 30 minutes; output: 4,000 tokens per call; concurrency: 1.
- Optional cost and input-token caps: unset. Existing global/account/service
  allowances remain in force.

These defaults provide two chances to revise a result while keeping the
shared-call ceiling, wall time, and per-call output reserve conservative.
They avoid reserving a high output ceiling or a maximum-length session by
default.

### Scheduling and validation

- Frontend and backend enforce the same ranges; at least two turns are required
  to allow one complete Investigator/Skeptic pair.
- The previous rule coupling turns to twice the rounds was removed, as was the
  launch check requiring a pair for every selected strategy.
- Portfolio scheduling rotates fairly among active strategies, reserves a
  complete pair when possible, and allows a pending Skeptic to use the final
  single turn. Unserved branches are explicitly marked Deferred with the
  reason in the Outcome.
- Tests cover 1, 3, and 5 strategies with shared limits of 3, 6, and 12 turns,
  including rotation/fairness and launching three strategies under a 3-turn
  ceiling.

### Currency input

USD cost input accepts a plain decimal or one leading `$`, with surrounding
whitespace. It validates cent precision and the $0.01–$100.00 range, then
persists the normalized numeric USD amount. Browser acceptance saved and
reloaded `  $2.00  ` as numeric `2`.

### 1 MB investigation and measurements

Session #11 was reported to fail when research transport exceeded the previous
hard 1,000,000-byte response cap. Research Responses bodies and completed SSE
streams now have an 8,000,000-byte cap, preserving a finite memory/transport
bound while allowing large valid Responses envelopes. Regressions accept a
1,010,000-byte response and reject responses/streams above 8 MB.

The 1 MB issue was not caused by the Maximum Regions project's stored data:
real browser acceptance measured its copied project JSON at 3,801 bytes and the
assembled provider context at 5,410 bytes. Thus the reported oversized
transport response and this sample's project/context overhead are distinct
measurements; the latter does not approach 1 MB.

## SECTION B — HAPPY-PATH RELIABILITY

### Root cause of previous failures

The reported failure modes included a 1 MB raw research-transport cutoff and
sessions ending after a Skeptic reported a productive stop even though the
review still had open objective obligations. Such a stop could leave a
persisted session terminal with only mixed/partial findings. The local browser
fixture also identified the Maximum Regions sample by a phrase absent from the
actual sample question; its matcher now recognizes the real line/region
wording. These are addressed without a sample-specific production code path.

### Fixes and actual sample execution evidence

`browser_checks/happy_path_reliability.py` used SIGMA's actual sample-copy UI,
API services, session worker, reports, storage, and a deterministic local
provider fixture in real Chrome. It passed on the final synchronized code
tree. The session dispatched exactly two fixture calls in order:
Investigator, then Skeptic. The Investigator supplied
`R(n) = 1 + n(n+1)/2`; the Skeptic reviewed the claim as an achieved candidate
with unverified status. The fixture supplied token usage so cost reservation
and reconciliation ran through the normal accounting path. The session ended
with status `ended`, two calls used, one saved finding artifact, and an
available estimated-cost record. No sample-specific formula or branch exists
in production implementation.

The deterministic run's usage was simulated by the fixture and displayed an
estimated cost of $0.004008. Actual paid provider calls and actual provider
cost: zero.

### Completion, saved result, report, and persistence

- Terminal session status: `ended`.
- Saved result: the formula `R(n) = 1 + n(n+1)/2`, recorded as an achieved,
  unverified candidate with reviewed reasoning.
- Report: TXT report export contained the saved formula and its unverified
  status.
- Persistence: after a browser refresh and reopening the copied project URL,
  the same session and artifact remained available and unchanged.
- The test checks no browser page errors and measured the 3,801-byte project
  copy and 5,410-byte assembled provider context above.

### Regression coverage and disposition

- Deterministic real-Chrome lifecycle: passed, including sample copy, `$2.00`
  currency round-trip, role order, accounting, terminal outcome, report,
  refresh, and reopen.
- Backend role/scheduling/completion tests and project report persistence
  tests: passed.
- Full `./sigma test`: passed on the final implementation tree.
- **MET:** local happy-path lifecycle, Investigator/Skeptic behavior, simulated
  reservation/accounting, completion detection, terminal status, persisted
  result, report availability, and refresh/reopen persistence.
- **UNMET:** none in deterministic local verification.
- **UNVERIFIED:** real provider-backed Play session, provider-specific
  completion quality, and live provider cost. The real session was not run
