## SECTION A — ISSUE #306

### Terminology changes

- “Skeptic iterations” is now “Research rounds”: one round is one
  Investigator→Skeptic exchange per strategy.
- “Maximum agent calls” is now “Maximum agent turns”: one turn is one provider
  call by either role, shared across all selected strategies.
- Progress, session metrics, summaries, and saved artifact labels use rounds
  and agent turns consistently.

### Defaults and rationale

- Research rounds: 2 (per-strategy ceiling).
- Maximum agent turns: 12 (shared ceiling; six full pairs in the one-strategy
  case).
- Duration: 30 minutes; output: 4,000 tokens per call; concurrency: 1.
- Optional cost and input-token caps: unset. Existing global/account/service
  allowances remain in force.

These defaults provide two chances to revise a result while keeping the
shared-call ceiling, wall time, and per-call output reserve conservative.
They avoid reserving a high output ceiling or a maximum-length session by
default.

### Scheduling and validation

- Frontend and backend enforce the same ranges; at least two turns are required
  to allow one complete Investigator/Skeptic pair.
- The previous rule coupling turns to twice the rounds was removed, as was the
  launch check requiring a pair for every selected strategy.
- Portfolio scheduling rotates fairly among active strategies, reserves a
  complete pair when possible, and allows a pending Skeptic to use the final
  single turn. Unserved branches are explicitly marked Deferred with the
  reason in the Outcome.
- Tests cover 1, 3, and 5 strategies with shared limits of 3, 6, and 12 turns,
  including rotation/fairness and launching three strategies under a 3-turn
  ceiling.

### Currency input

USD cost input accepts a plain decimal or one leading `$`, with surrounding
whitespace. It validates cent precision and the $0.01–$100.00 range, then
persists the normalized numeric USD amount. Browser acceptance saved and
reloaded `  $2.00  ` as numeric `2`.

### 1 MB investigation and measurements

Session #11 was reported to fail when research transport exceeded the previous
hard 1,000,000-byte response cap. Research Responses bodies and completed SSE
streams now have an 8,000,000-byte cap, preserving a finite memory/transport
bound while allowing large valid Responses envelopes. Regressions accept a
1,010,000-byte response and reject responses/streams above 8 MB.

The 1 MB issue was not caused by the Maximum Regions project's stored data:
real browser acceptance measured its copied project JSON at 3,801 bytes and the
assembled provider context at 5,410 bytes. Thus the reported oversized
transport response and this sample's project/context overhead are distinct
measurements; the latter does not approach 1 MB.

### Deterministic Chrome scope and security limits

The Maximum Regions acceptance runs the scripted four-turn role sequence and
checks application persistence, report generation, and fixture-simulated usage
and cost reconciliation. Provider outputs and token counts are predetermined.
It is evidence for deterministic UI/backend orchestration and persistence; it
is not evidence of live model quality, real provider usage, or real provider
cost. The acceptance launches Chrome with `--disable-web-security` and routes
`/api` calls from the UI origin to the separate local fixture origin. Therefore
it does not verify normal same-origin behavior, CORS enforcement, or browser
security boundaries. No production-origin acceptance is claimed.

### 8 MB response bound risk statement

The per-response body and completed-stream limit remains finite at 8,000,000
bytes. The oversized-response regression still accepts a 1,010,000-byte
successful response and rejects a response/stream that crosses the 8 MB bound.
No evidence from a live provider establishes that 8 MB payloads are needed; live
payload size, parsing peak memory, and production concurrency memory impact
remain **UNVERIFIED**. The bound applies to each response. Local portfolio
execution can have three provider calls in flight, so raw response buffers can
approach 24 MB in aggregate before JSON/SSE parsing and object allocations;
this is not a total process-memory ceiling. Hosted sponsored execution serializes
provider concurrency to one. Keep the bound finite and do not increase it absent
measured provider evidence.
