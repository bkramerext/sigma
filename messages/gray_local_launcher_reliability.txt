Changes

- `./sigma shutdown` now scans the private per-user instance registry and uses
  each verifiable launcher's existing private control socket, including
  instances started from other checkout directories. New owner records include
  the canonical checkout root; older records derive it from the recorded
  launcher command and validate the checkout identity.
- `./sigma start --nav` stops other registered launchers and then scans fixed
  ports for verified orphan SIGMA servers before binding. Startup still refuses
  to signal unknown listeners and keeps the fixed 8000/5173 ports.
- Recovery removes dead owner records, refused control sockets, and partial
  owner temp files under the per-checkout lock. Kernel flock ownership releases
  when a process exits; the lock-file inode remains stable to avoid lock-file
  replacement races.
- Orphan ownership requires same OS user, a valid checkout, exact server
  command, unchanged process birth identity, a per-launch environment marker,
  and the same marker served by the candidate endpoint. Unverified port
  occupants are reported with port, PID, executable and working directory when
  available.
- `docs/GETTING-STARTED.md` and `docs/DECISIONS.md` describe the updated local
  behavior and ownership boundary. `tests/ui_registry.py` and
  `tests/ui_orphans.py` cover cross-checkout, stale state, unrelated listeners,
  and PID reuse; `tests/ui_lifecycle.py` now covers actual cross-checkout
  shutdown/start replacement when run in an isolated free-port environment.

Acceptance matrix
