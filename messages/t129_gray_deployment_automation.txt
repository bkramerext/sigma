Implemented:
- Added `deploy/deploy-gce-release.py` for initial start and repeat upgrades by full lowercase Git SHA. It checks protected configuration and host preflight, refuses dirty trees, fetches the exact commit and builds backend/frontend images tagged with that SHA before maintenance. It atomically changes only `SIGMA_RELEASE`, re-runs preflight against the selected checkout, starts through systemd, then checks all container health statuses, backend/frontend image identity, checked-out SHA, active unit and mounted state directory.
- A repeat deployment of the active SHA verifies preflight and readiness and does not mutate the release. Initial start requires the service inactive and disabled. Upgrades require explicit `--backup-verified` and `--schema-compatible` assertions.
- Candidate startup/health failure restores the previous checkout and release pin and attempts to restart and verify the previous release. Recovery failure directs the operator to keep ingress closed and inspect sanitized systemd diagnostics. No `down`, volume removal, state write, credential edit or sandbox mutation is performed.
- Added automated tests for idempotency, missing deploy.env, failed startup/recovery, diagnostic redaction, and exact environment/state preservation. Added the test to the actual `./sigma test` plan.
