## Architecture and files

- `src/sigma/session_log.py`: isolated append-only Markdown session store; UUID project/session paths, byte-framed event records, serialized/fsynced appends, safe tail recovery, redaction, stable derived short names, incremental reads, cleanup.
- `src/sigma/research_sessions.py`: best-effort hooks at the actual provider request/response boundary, request ID pairing, operational events and cross-strategy evidence availability/inclusion metadata.
- `src/sigma/api.py`: owner-authorized incremental log read and Markdown download; project deletion cleanup.
- `frontend/src/SessionLogButton.tsx`, `frontend/src/SessionLogPage.tsx`, `frontend/src/main.tsx`, `frontend/src/style.css`, `frontend/src/strategies.css`: adjacent Log control and independent live polling window with paired collapsible provider exchange blocks.
- `tests/session_log.py`, `tests/research_sessions.py`, `tests/cloud_research_api.py`, registration in `src/sigma/tooling.py`: storage/recovery, real serialized provider request capture, redaction, auth and export exclusion regressions.
- `browser_checks/issue301_session_log.py`: real Chromium window, incremental update, pairing, download, refresh and close check.
- `docs/evaluations/issue301/session-log-chromium.png`: captured browser evidence.
- `docs/STATUS.md` and `docs/TICKET_TRACKING.md`: tracking update.

Logs are kept outside project JSON exports. Provider logging is best-effort and exceptions are swallowed so they do not fail research. One stable title-derived short name is persisted as an adjacent sidecar per project; no extra naming provider call is made.

- Log control is adjacent to Play/Stop/Resume, using reduced existing icon treatments and preserving color.
- Separate window updates by incremental polling; title and heading use `<Short Project Name>, Session <N>`.
- Actual provider serialized request and returned response are captured at the provider boundary and paired by stable request ID, with raw response wire data, timing, usage/cost/reservation metadata, failures, round/strategy/turn/role identifiers and request identifiers.

- One Markdown file per session, append-only framed writes with serialization, fsync, partial-tail recovery, multiline content and VS Code-readable output.
- Credentials/secrets are redacted before persistence; logger failures are best-effort.
- Incremental viewing/download ownership checks, project deletion cleanup, and omission from project JSON export.
- Stable short name reuse across sessions without a separate paid naming call.
- Real Chromium interaction verified; persistence/restart and concurrency have deterministic backend regression coverage.
