## Architecture and files

- `src/sigma/session_log.py`: isolated one-Markdown-file-per-session store, UUID-derived paths, ordered background writer, framed append records, `fsync`, read-only torn-frame recovery, credential redaction, stable names, incremental reads, and project/session cleanup.
- `src/sigma/research_sessions.py`: best-effort hooks at the actual provider boundary. It pairs complete serialized requests and provider response wire data by request ID and records operational/cross-strategy metadata. After an Investigator response passes existing output validation, the validated claim supplies a compact project subject label. This reuses existing model output and makes no naming request.
- `src/sigma/api.py`: existing owner-scoped session checks for incremental retrieval/download and project deletion cleanup. Deletion stops active sessions, then awaits queued log cleanup off the event loop.
- `frontend/src/SessionLogPage.tsx`: one fetch at a time using recursive timeout polling, monotone byte cursor, and sequence-based event deduplication.
- `frontend/src/SessionLogButton.tsx`, `frontend/src/main.tsx`, `frontend/src/style.css`, `frontend/src/strategies.css`: Log control and independent window.
- `tests/session_log.py`: ordering, delayed storage, append-only bytes, torn-write recovery across restart, multiline payload, redaction, persistence, cleanup, and stable naming.
- `tests/research_sessions.py`: actual request/response capture and stable name derived from validated Investigator output without extra provider calls.
- `tests/cloud_research_api.py`: owner and cross-user read/download authorization plus deletion of an active session and its project log tree.
- `browser_checks/issue301_session_log.py`: standalone real-Chromium popup behavior with deterministic mocked API responses.
- `browser_checks/issue301_integrated.py`: real Chromium over HTTP to the production `session_log.append`, `read`, and `log_path` service, using deterministic project/session lookup fixtures. It delays a response, replays an event, and checks no overlapping requests, monotone cursors, deduplication, refresh, and download.
- Screenshots: [standalone browser check](../docs/evaluations/issue301/session-log-chromium.png) and [integrated browser check](../docs/evaluations/issue301/session-log-integrated-chromium.png).
- Tracking: `docs/STATUS.md`, `docs/TICKET_TRACKING.md`.

Provider log events are queued to one dedicated daemon writer. Disk locks, scans, serialization/redaction, and `fsync` occur on that thread, not on the research execution path. Queue order preserves event order within the process; `flock` serializes processes. Graceful interpreter shutdown drains the queue. Existing project JSON exports remain free of diagnostics.

## Acceptance status

### MET

- AI-derived, subject-based short name is extracted from the first successful validated Investigator claim and atomically persisted once for the project. Later sessions reuse it. No extra naming call; research output schema/validation is unchanged.
- Disk operations are off the research path. A delayed-storage regression confirms enqueue returns promptly and queued concurrent events preserve order.
- The Markdown file is strictly append-only: torn records are skipped without truncation or rewrite. Valid frames appended after a torn tail remain readable; subprocess recovery verifies existing bytes are unchanged.
- Frontend requests cannot overlap. A monotone cursor ref and sequence set prevent regressions/duplicates; the browser integration delays responses and deliberately replays an old event.
- Active-session project deletion stops the worker and removes the full log directory; authorization is enforced for incremental retrieval and download; request/response content is redacted; project exports omit logs.
- Real Chromium has been exercised both with mocked API behavior and with HTTP responses from the production storage service.

### UNMET

- None identified in the four adversarial findings.

### UNVERIFIED / limitations

- The integrated browser server uses deterministic project/session lookup fixtures rather than starting the full authenticated API server. The production FastAPI routes, owner checks, active deletion and downloads are independently covered by `TestClient` API tests.
- The short name is a compact deterministic subject extraction from an already AI-produced validated claim. Before a successful Investigator claim exists, the window temporarily displays `Research Project`.
- The writer queue is in memory. Graceful shutdown drains it, and a torn on-disk append is recovered without modification. An abrupt process kill before a queued event reaches disk can lose that not-yet-written event; logging remains best-effort so it cannot delay/fail research.
- The graph-present sandbox scenario is skipped because its configured image is unavailable.
- No paid provider calls occurred.
