Verified by source inspection:
- `sigma.service` orders after/requires the system Docker and sandbox services,
  and `RequiresMountsFor=/srv/sigma-state` supplies the mount dependency/order.
  Preflight runs before guarded startup.
- State storage maps only `/srv/sigma-state/auth` to the backend; startup sets
  it to UID/GID 10001 mode 0700. The sandbox account is intended to lack access
  to the root-owned mode-0700 state root.
- Research jobs use UID 65532, `--network=none`, read-only root, no
  capabilities, `no-new-privileges`, bounded memory/CPU/PIDs/time, and receive
  no state or daemon socket mount. The app backend does have the separate
  rootless daemon socket, so security depends on the sandbox user's limited
  host permissions.
- T171's preflight change enforces Compose service security/resource settings
  and edge port policy. The package's Caddy edge publishes host 80/443 on
  `0.0.0.0` by default. This conflicts with the operator-reported existing host
  Caddy on the same ports; choose one edge or implement a reviewed loopback
  upstream mode before production startup.
