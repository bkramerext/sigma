Scope and architecture
----------------------
Gate A private-workspace isolation and Gate C public Demo remain the merged
main implementations. This change prepares the parent T22 cloud deployment
path without changing Green's Gate B execution/provider/budget implementation.

The selected hybrid design serves the Vite build and `/api/*` routing from a
Cloudflare Worker. The Worker is bound to the configurable HTTPS public
origin. It strips incoming Access and identity headers, injects its own
Access Service Token to an HTTPS API origin, and proxies the request without
changing the browser's public Origin or session cookie. The API host is
reachable through a remotely managed Cloudflare Tunnel with an Access Service
Auth policy that permits only that Worker token. The host exposes the API on
loopback only. FastAPI runs in an unprivileged, read-only container with a
durable host volume for Google auth SQLite and Gate A workspace/project/session/
artifact data. The Gate C snapshot remains a separately configured immutable
image resource and startup rejects any snapshot resolving inside private
storage. Uvicorn access logging is disabled to avoid OAuth callback query
values in logs.

Cloudflare container filesystems are ephemeral by default, so this does not
put SIGMA's current POSIX filesystem/SQLite requirements on an ephemeral
Worker/container disk. No D1/R2 storage rewrite is included. Cloudflare's
Workers pricing page, checked 2026-10-23, lists Free at 100,000 requests/day
and 10ms CPU per invocation; Workers Paid has a $5/month minimum and metered
overages; static asset requests are free at present. This does not include
the durable host, disk, backups, custom-domain registration, or model usage.
Pricing: https://developers.cloudflare.com/workers/platform/pricing/
Container persistence note: https://developers.cloudflare.com/containers/faq/

Prerequisites / secret handling
-------------------------------
- Linux host with Docker Engine and a durable filesystem; run the API on the
  Linux host, not an ephemeral container disk. The host must retain the data
  root across container replacement.
- Cloudflare account, verified custom domain or a configured workers.dev
  public URL, remotely managed Tunnel hostname, Access Service Auth policy,
  and least-privilege Worker deployment API token. This PR created none.
- Google OAuth Web client ID/secret, exact public origin and callback
  `https://<public-host>/api/cloud-auth/callback`, bootstrap admin email, and
  admin contact email. These must be operator-supplied. No Google login was
  performed.
- `/etc/sigma/runtime.env` mode 0600; `/etc/sigma/worker-secrets.json` mode
  0600; `/etc/sigma/tunnel-token` owner root/group 65532 mode 0640. Secrets
  remain outside source, image layers, generated assets, and browser code.
  Never enable Uvicorn access logs.
- Gate B must integrate and verify durable bounded execution, concurrency,
  per-user provider authorization and global spend controls before cloud
  research is opened to users. This deployment work does not duplicate that
  behavior or claim cloud research readiness.
- An encrypted off-host backup destination and key-management procedure are
  operator prerequisites. The included local archive is mode 0600 but is not
  itself encrypted.

Deployment commands (Linux operator host)
-----------------------------------------
From the repo root, set up the durable volume and backend:

  sudo install -d -o root -g root -m 0700 /etc/sigma
  install -d -m 0700 "$HOME/.config/sigma"
  install -m 0600 deploy/runtime.env.example "$HOME/.config/sigma/runtime.env"
  ${EDITOR:-vi} "$HOME/.config/sigma/runtime.env"
  sudo deploy/install-volume.sh /srv/sigma/data
  sudo deploy/build-api.sh sigma-api:2026-10-23-a1b2c3d
  sudo deploy/run-api.sh /srv/sigma/data "$HOME/.config/sigma/runtime.env" sigma-api:2026-10-23-a1b2c3d

Configure the Tunnel in Cloudflare to reach the host's loopback port 8000;
set its HTTP Host Header to the exact public SIGMA hostname. Configure
Cloudflare Access Service Auth on the origin hostname for only the Worker
service token. Then:

  sudo install -o root -g 65532 -m 0640 /dev/null /etc/sigma/tunnel-token
  sudoedit /etc/sigma/tunnel-token
  sudo chown root:65532 /etc/sigma/tunnel-token
  sudo chmod 0640 /etc/sigma/tunnel-token
  sudo deploy/run-tunnel.sh /etc/sigma/tunnel-token
  install -m 0600 /dev/null "$HOME/.config/sigma/worker-secrets.json"
  ${EDITOR:-vi} "$HOME/.config/sigma/worker-secrets.json"
  SIGMA_WORKER_SECRETS_FILE="$HOME/.config/sigma/worker-secrets.json" deploy/deploy-worker.sh

Set the Worker's custom hostname equal to SIGMA_PUBLIC_ORIGIN. Then verify:

  curl --fail --show-error https://sigma.example.org/healthz
  curl --fail --show-error https://sigma.example.org/api/cloud-demo/ > /tmp/sigma-demo.json
  curl -i https://sigma.example.org/api/projects/recent  # expected 401
  docker inspect --format '{{.State.Health.Status}}' sigma-api

Worker rollback uses `deploy/rollback-worker.sh PREVIOUS_VERSION_ID`, replacing
the placeholder with the version ID from Wrangler's deployment history.
Backend rollback replaces the container while reusing the durable volume:

  sudo deploy/stop-api.sh
  sudo deploy/run-api.sh /srv/sigma/data "$HOME/.config/sigma/runtime.env" sigma-api:2026-10-22-cafe123

Keep immutable backend tags and the prior Worker version until the rollback
has passed health and Demo checks. The runbook is `deploy/README.md`.

Backup and restore commands
---------------------------
Create a private stop-the-world archive outside the data root:

  sudo deploy/backup.sh /srv/sigma/data /srv/sigma-backups/sigma-20261023T000000Z.tar.gz
  AGE_RECIPIENT='age1replace-with-approved-public-recipient'
  age -r "$AGE_RECIPIENT" -o /srv/sigma-backups/sigma-20261023T000000Z.tar.gz.age /srv/sigma-backups/sigma-20261023T000000Z.tar.gz

Encrypt before copying off-host. Restore only to a new empty directory, then
install the volume marker; never restore over the active directory:

  age -d -i /etc/sigma/backup-identity.age -o /srv/sigma-restore/backup.tar.gz /srv/sigma-backups/sigma-20261023T000000Z.tar.gz.age
  sudo docker stop sigma-api
  sudo install -d -o 10001 -g 10001 -m 0700 /srv/sigma/data-restored
  sudo python3 ops/data_archive.py restore /srv/sigma-restore/backup.tar.gz /srv/sigma/data-restored --uid 10001 --gid 10001
  sudo install -o 10001 -g 10001 -m 0600 /dev/null /srv/sigma/data-restored/.sigma-deployment-volume-v1
  sudo sh -c "printf 'SIGMA durable cloud data volume v1\\n' > /srv/sigma/data-restored/.sigma-deployment-volume-v1"
  sudo chown 10001:10001 /srv/sigma/data-restored/.sigma-deployment-volume-v1
  sudo docker rm sigma-api
  sudo deploy/run-api.sh /srv/sigma/data-restored /etc/sigma/runtime.env sigma-api:2026-10-22-cafe123
  curl --fail https://sigma.example.org/healthz

The archive contains auth SQLite and private workspaces (including project,
session, and artifact data). The public Demo is in the tagged image and is
restored by image rollback. Keep original data and validate representative
accounts/projects before reopening access.
