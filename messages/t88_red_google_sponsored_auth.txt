Implementation

- Added a persistent account record keyed by verified Google subject. It stores
  verified email, current role/access state, hosted workspace mapping, personal
  versus sponsored access, sponsorship eligibility, and the last server-checked
  connection status. Grant role changes and revocation update role/eligibility.
  Spend, held reservations and unknown attempts remain in T99's usage ledger.
- After an authorized callback, the app creates/loads the hosted per-subject
  workspace before issuing the session. Protected request middleware continues
  to enforce active invitations and admin role; guest APIs cannot access private
  workspaces or inference.
- Added a protected, non-generating sponsored connection check using the
  server-held credential and provider model catalog. It returns only safe state
  and persists the result. Personal local-auth mode records the existing
  connection service's status. No credential material is sent to the browser.
- Replaced the separate hosted Google and model controls with one two-line
  role/model pill and one account/model dialog. Added guest Explore-only entry,
  explicit uninvited-account screen, provider retry/recovery states, sponsor
  budget display, and clearing of remembered project selection at sign-out.
- Added a browser fixture app that mocks the external provider boundary while
  using SIGMA's real connection adapter, account persistence, workspace and
  project APIs. Extended deterministic auth and sponsored API coverage.

Integration overlaps and conflicts

- T22.2 / PR #37 supplies and remains authoritative for Google OIDC, invitations,
  admin grants, session revocation and denied-account behavior. This PR extends
  its persistent auth DB with account state.
- T174 / issue #192 and PR #148's preparation cover subject-keyed hosted
  workspaces, project ownership and path confinement. Reused those services;
  no second storage mapping was introduced.
- T99 / PR #107 and T99.1 / PR #110 supply hosted sponsor credential selection,
  budget admission, spend reconciliation and failure holds. This PR adds the
  user-facing connectivity state only; it does not change budget limits.
- T43.2 / PRs #166 and #169 cover multi-account fixture acceptance. Its real
  Chrome script is updated to assert the unified account/model pill and extend
  the actual hosted connection-check flow.
- Architectural boundary: T22.2's explicit local-auth mode preserves the
  traditional shared local project root. It therefore has no per-subject
  workspace, by design. Hosted mode uses T174 isolation. Changing local project
  ownership would conflict with T22.2's local compatibility contract and needs
  coordinator/product direction. Hosted mode also intentionally rejects
  personal ChatGPT OAuth under T172; it uses only SIGMA-sponsored inference.
