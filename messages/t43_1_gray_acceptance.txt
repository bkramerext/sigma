Root cause and security disposition
The active local API reported Google auth `enabled: false`. This checkout's `.env` had Google OAuth client credentials, and `~/.bashrc` contained the bootstrap-email export, but the actual launcher environment lacked `SIGMA_CLOUD_BOOTSTRAP_ADMIN_EMAIL`. The launcher intentionally reads checkout `.env` without executing shell files; when the launching shell has not sourced `.bashrc`, the bootstrap value is unavailable. A second UI defect compounded this: CloudAuthGate omitted local identity context when auth was disabled, so the Home pill showed “Coming Soon” and could not explain the missing setting.

SIGMA does not infer the first administrator from the Google OAuth client or silently enable authentication. The pill now opens a setup diagnostic listing missing variable names only. It presents Continue with Google only when auth is enabled and ready. The launcher prints an actionable warning for OAuth client credentials without the bootstrap email. The operator can load the configured value in the launching shell with `source ~/.bashrc`, verify presence with `test -n "$SIGMA_CLOUD_BOOTSTRAP_ADMIN_EMAIL"`, and restart using `./sigma start --nav`. Email/subject binding, verified Google identity, local/hosted separation, and authorization enforcement remain intact.
