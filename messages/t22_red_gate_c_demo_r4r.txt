Scope delivered

- Replaced the hosted `/demo` placeholder with a copper/dark SIGMA research experience backed by one deterministic audit snapshot adapted from `samples/handshake-count-easy/project.json`. The snapshot has stable IDs/timestamps, project metadata, two strategies, a saved session/outcome, analysis, research evidence, a finite computation and a captured CSV artifact. The CSV and finite result are explicitly illustrative and not presented as a proof.
- `SIGMA_CLOUD_DEMO_AUDIT` selects the one deployment-controlled snapshot. The server resolves it, requires a regular service-owned file and service-owned containing directory that are not group/other-writable, and rejects it inside either `SIGMA_CLOUD_WORKSPACES_ROOT` or the default `$SIGMA_CLOUD_AUTH_HOME/workspaces`. Resolution catches parent-symlink aliases. Missing or unsafe configuration fails closed; local mode returns 404 for the hosted Demo API and retains its existing unrestricted app behavior.
- Added a dedicated mounted read-only sub-application for `/api/cloud-demo/` and `/api/cloud-demo/report`. This is outside the root app's private-workspace dependency, so anonymous and denied identities do not need a workspace. The parent cloud-auth middleware permits only GET/HEAD to the two exact endpoints. No mutable route, project lookup, AI call, agent call, or scientific execution is available on the Demo surface.
- Extended the existing A17.5 export dialog with LaTeX. Audit JSON plus Text, HTML and LaTeX reports are produced from the snapshot. Added anonymous Home Demo navigation; the existing denied account's invitation flow remains reachable from the Demo.
- Updated parent `tickets/t22.md`, `TICKET_TRACKING.md`, `docs/STATUS.md`, `docs/CLOUD-AUTH.md`, and the existing cloud auth browser check. No workspace storage implementation was introduced or changed.
