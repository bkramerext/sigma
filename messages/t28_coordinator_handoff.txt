T28 — Computational evidence and artifact comprehension

Status: implemented on feature/t28-computational-evidence; PR is ready for review (R4R).

What changed
- Existing sandbox artifacts can now be inspected safely without introducing another execution path. PNG/JPEG get a bounded 64×20 grayscale rendering; common UTF-8 text/CSV/JSON formats get an escaped preview capped at 1,400 characters. Inspection reads files through the existing sidecar hash check.
- Unsupported, corrupt, oversized, missing, and integrity-mismatched files receive explicit notices. A maximum of two artifacts are inspected per execution; image decode is capped at 2 million pixels and one file at 4 MB.
- Python and SageMath prior-session computations now reach Investigator and Skeptic with the original source, output/error, execution status, runtime, origin, limitations, and artifact previews. Structured citations are checked against the supplied evidence. Failed runs cannot be claimed as results, and reused runs retain their original IDs/provenance.
- Per-runtime execution status summaries now report Python and SageMath separately, including each recorded status. Shared/recovered evidence is deduplicated by runtime and execution ID; artifact byte accounting remains deduplicated.
- Preview snapshots are included in role-step evidence for audit; original execution records are unchanged.

Limitations
- Grayscale rendering does not OCR axis labels, distinguish colors, recover exact pixel values, or establish a plot's scientific interpretation. Compare the picture with its code and printed values.
- Formats other than bounded raster images and recognized UTF-8 text are explicitly unsupported; original artifacts remain available through the existing stored references.
- Pillow 13.0.0 is a pinned dependency for safe common-raster decoding.
