## Finding and correction

Confirmed the SHA mismatch risk. Production Compose tags backend/frontend
images with `SIGMA_RELEASE` but had build contexts rooted at the mutable
`/opt/sigma/current`; `start-gce.sh` used `up -d` without `--no-build`. An
operator could therefore start images built from another HEAD or dirty files
under the requested SHA tag. The runbook did not bind image content to the
requested commit.

Added `deploy/release_image.py build CHECKOUT FULL_SHA`. It validates a full
lowercase SHA resolves to that exact Git commit, exports that commit's tree
with `git archive`, then builds both amd64 images from that isolated context
and applies the OCI revision label. Startup checks labels before Compose,
uses `--no-build`, and records the requested source commit, running container
IDs, actual image IDs and available repository digests in a per-release JSON
file. Existing rollback gates/state handling remain intact; mismatched or
unlabelled rollback images are refused by the same startup provenance check.
