## Findings and implementation

- Reviewed issue #66, current Google OIDC/cloud-auth and ChatGPT SIWC flows,
  existing API/browser tests, and the local persistent-disk acceptance contract.
- Existing tests already cover Google authorized A→B switching, denied
  identities, session revocation/restart, and workspace isolation. ChatGPT
  service tests covered adding/selecting two registrations, but did not assert
  that disconnecting one selected identity preserves the other one's tokens.
- Added a two-subject ChatGPT regression. It verifies independent subject,
  email, and token records; disconnects account A; selects still-connected B;
  then reconnects A into the same record and confirms B's credentials remain
  unchanged.
- Extended the isolated Chrome SIWC scenario to connect account B after A,
  assert B remains active after page reload, and switch back to A through the
  existing account selection endpoint. Added a fixture Google A principal so
  the local UI permits ChatGPT actions.
- Kept the hosted-mode 403 guard intact. The Google browser test uses its
  existing deterministic test-only identity adapter; neither test enables
  personal ChatGPT OAuth in hosted mode.
