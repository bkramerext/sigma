# T301: Context-aware mathematical Markdown

**Owner:** Blue  
**Branch:** `blue/t301-math-markdown` from current `origin/main`  
**Scope:** Refine existing AI-assisted conversion and `RenderedMarkdown`; do not add a second renderer or change visual design.

## Objective

Render math naturally inside research prose while preserving programming identifiers, technical strings, Markdown structure, and the source project. Use sentence context in the existing AI conversion prompt and conservative local recognition in the existing KaTeX renderer. Do not add a provider call per block or sentence.

## Acceptance

- Recognize contextual fractions, equations, and lower-case indexed variables embedded in prose, including multiple formulas in one paragraph.
- Keep upper snake case identifiers, code, links/URLs, paths, dates, versions, currency, and ordinary slash-separated wording literal.
- Preserve paired dollar and legacy TeX delimiters, multiline display math, escaped delimiters, and unmatched delimiter text safely.
- Render math in paragraphs, emphasis, nested lists, blockquotes, and GFM tables; retain valid Markdown structure.
- Exercise the existing `/api/projects/text/convert` route and actual `RenderedMarkdown` in a real browser with one shared representative fixture. Check semantic preservation and save an inspectable screenshot.
- Run focused tests and `./sigma test`. Live provider quality may be UNVERIFIED when it requires paid inference; do not make paid calls.

## Constraints and delivery

Preserve project identity, original text, research history, security behavior, and existing visual design. Do not modify authentication, sponsorship, onboarding, or unrelated UI polish. One PR to `main`, no self-merge. Commit a coordinator handoff under `messages/` with test evidence, screenshot, example input/output, limitations, and MET/UNMET/UNVERIFIED status.
