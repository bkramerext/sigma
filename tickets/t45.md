# T45 — High priority: Long-form TeX paper generation under model output limits

**Priority:** HIGH (paper quality / core research output)
**Status:** Implemented on `t45-long-paper-generation`; pending coordinator review.
Implementation was explicitly authorized by the user after the original investigation-only proposal.
**Suggested owner:** Green (T20 paper-generation familiarity)
**Related:** T20 AI-authored papers, report/export pipeline, provider output and context budgets

## Problem

SIGMA can generate AI-authored LaTeX papers, but a single bounded model response cannot reliably hold a substantive research paper. Character caps may truncate prose or TeX mid-command, and provider output-token, request-envelope, context-window, and stored-field limits are not interchangeable. Simply raising one character limit is unlikely to support long papers robustly.

We need a reliable path from a potentially large, evidence-rich research record to a coherent, complete, well-typeset paper without losing source attribution or pretending omitted material was reviewed.

## Investigation

1. **Map actual limits and failure modes.** Trace T20's end-to-end path from evidence snapshot and prompt assembly through provider call, structured response, persistence, validation, TeX rendering, PDF compilation, and UI/download. Identify every relevant byte/character/token/context/envelope/field limit, with file/line references and tests. Separate intentional safety bounds from accidental reuse of limits intended for other features. Determine what happens today on overflow, partial output, timeout, cancellation, and restart.
2. **Evaluate architectures, not just larger caps.** Compare one-shot generation with a staged process: evidence inventory and outline; section-by-section generation using explicit source references; durable section checkpoints; cross-section consistency/claim review; deterministic TeX assembly and PDF compilation. Consider bounded retries of individual sections, model context constraints, token budgets, cost and latency, and versioning.
3. **Preserve evidence and coherence.** Define how the full frozen research snapshot is indexed, how evidence is selected for each section, how important contradictory or negative results are retained, and how cross-references, definitions, theorem numbering, citations, notation, and conclusions stay consistent. The model must not invent proof steps, external citations, or verification.
4. **Define operational behavior.** Show honest progress across stages, support cancellation/restart/resume without duplicating completed work, prevent accidental extra provider calls, preserve immutable source and paper versions, and surface actionable failures. Explicitly account for ChatGPT-plan vs API billing identity and limits; no silent fallback.
5. **Measure representative cases.** Use an existing small paper and a deliberately larger evidence fixture whose desired paper exceeds today's single-response budget. Deterministic/mock tests first. Compare output completeness, evidence fidelity, TeX/PDF compilation, time and projected usage. Do not make live/paid provider calls without explicit authorization.

## Deliverable

Write a concise design and findings document in `docs/` with:
- A table of actual limits, their sources, and observed behavior.
- At least two feasible designs with tradeoffs and a **recommended incremental implementation plan**, including clear per-stage bounds.
- A concrete acceptance plan covering long papers, partial failures, reproducibility, evidence fidelity, and compiled PDF quality.
- Any small deterministic reproduction harness/tests needed to demonstrate the current failure mode.

**Do not implement a broad redesign or silently increase safety limits during investigation.** Bring the proposed architecture and scope to the coordinator for approval before implementation.

## Acceptance for investigation

- Every important size limit and truncation point in the current paper pipeline is identified with code references.
- Reproduction demonstrates a paper-length case that the current one-shot path cannot complete safely.
- Proposed design supports papers substantially larger than one model response, with bounded per-stage work, stable provenance, and resumability.
- Recommendation includes specific risks, implementation slices, and tests, rather than an unbounded proposal.
- `./sigma test` passes for any committed code or test changes; report what was actually exercised.

Work on a dedicated branch and open an R4R PR for the investigation artifacts. No provider calls, feature expansion, or self-merge. Do not coordinate directly with other Codex workers; report dependencies through the ChatGPT coordinator.

## Implementation result

Long-form generation, user-confirmed provider-call ceilings, streamed progress,
durable per-stage checkpoints, source-linked evidence batching, expanded bounded
Tectonic compilation, a 483,485-byte Xenopus regression, and a focused real-Chrome
fixture check are implemented on the branch. See
[`docs/LONG-PAPER-GENERATION.md`](../docs/LONG-PAPER-GENERATION.md) for exact
bounds, behavior, and verification. No live provider calls were made.
