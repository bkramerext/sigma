# T46 — Home About action and product tour

**Priority:** Medium-high (product onboarding and showcase)
**Status:** Proposed; not assigned
**Suggested owner:** Gray (Home/UI)
**Area:** Home page, product education, responsive UI

## Objective

Add an obvious, polished **About** action to the Home page. It should open an engaging, easy-to-scan introduction to **SIGMA: Strategy Investigation, Generation, Measurement & Assessment** that explains what the product does, why it is interesting, and how a new user can start. This is a product-facing experience, not a developer README, release notes, or an indiscriminate feature inventory.

## Product story and content

Use concise, inviting, accurate language and clear visual hierarchy. Convey:

- **What SIGMA is:** an AI-assisted research workspace for exploring hard questions with multiple agents and durable evidence, not a guaranteed theorem prover.
- **Investigations, Strategies, Sessions:** a project defines the overarching question; strategies are narrow, persistent, branchable research approaches; sessions are bounded attempts that investigate them and preserve their history.
- **How agents work:** Investigator and Skeptic challenge and refine ideas; research can span strategies and cycles, with explicit status, limitations, and human intervention.
- **Beyond conversation:** research artifacts, provenance, computational experiments with isolated Python/SageMath where available, outcomes, and exportable reports/LaTeX or AI-authored papers.
- **Interesting things to try:** start with a curated sample; explore a mathematical problem, scientific hypothesis, or another open-ended question; inspect the critique and evidence; fork a strategy and run another session; export a report.
- **How to begin:** a short, practical path from Home (open sample or create project, add/generate strategy, start a research session, inspect results).
- **Honest boundaries:** model-generated conclusions are not independently verified proofs; availability of connected models, computation, paper generation, and hosted/cloud features may depend on the current environment, permissions, or configuration. Do not advertise planned features as shipped.

Aim for a delightful first impression: a strong introductory headline, a short explanation of the research loop, selected feature highlights, and a clear action back to the Home workflow. Use SIGMA's existing copper/black visual language and established typography, spacing, buttons, disclosure and focus behavior. A modest diagram or simple iconography is welcome if it genuinely improves comprehension; avoid an elaborate animated marketing site or a new design system.

## Interaction requirements

1. Put a discoverable **About** action on Home without disrupting existing New/Open/Samples/Recent actions or the artwork/layout.
2. Use an appropriate dialog, sheet, or in-app view consistent with current navigation. It must close cleanly and return the user to the exact Home state; do not change project selection or create data.
3. Support desktop and narrow/mobile widths, keyboard navigation, visible focus, accessible headings, dialog semantics if applicable, and Escape/close behavior.
4. Keep text readable and sections scannable; avoid overwhelming users with every technical detail. Content should be maintained in a straightforward place in the frontend.
5. No network requests, model calls, authentication, or billing are required to open About. It should work in local and hosted modes, with accurate wording in both.
6. If a CTA links to Samples or New Project, use existing workflows and do not invent navigation behavior.

## Acceptance

- A first-time user can answer **what SIGMA does, what makes it different, how to try it, and what its limits are** after reading About.
- No misleading promises of proof verification, cloud availability, or autonomous success.
- Visual quality is consistent with the rest of SIGMA, including narrow viewport and keyboard/focus behavior.
- Home's existing actions, project state, and navigation remain unchanged.
- Add focused UI tests and a real-Chrome desktop/narrow-screen acceptance check. Run `./sigma test`; report what was actually verified.
- Provide screenshots or concise visual acceptance notes and an R4R PR. Do not merge or perform live provider calls.

**Scope control:** This ticket is an About/onboarding surface only. No feature implementation, redesign of Home, external marketing page, or documentation overhaul. If a larger UX change seems necessary, propose it before coding.
