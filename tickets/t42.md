# T42 - Google Cloud deployment readiness

Owner: Red
Status: ASSIGNED
Target: current main, isolated T42 branch and PR

## Objective
Prepare a reproducible, secure, cost-estimated deployment of SIGMA on **Google Cloud Compute Engine only**, ready for operator-approved provisioning within approximately one day. This ticket is preparation, not authorization to activate billing, provision cloud resources, deploy remotely, or call paid providers.

## Architecture and boundaries
- Compute Engine Linux VM running SIGMA's Python/FastAPI backend, SPA, and research agents in Docker.
- Support SIGMA's Python dependencies and SageMath requirements. Confirm practical image size, RAM, CPU, startup time, and build viability.
- Persistent disk/state for projects, sessions, artifacts, cloud auth/accounting SQLite, and any other mutable state. Document backups, restart behavior, and restore.
- Google OAuth: local development and production use separate OAuth clients. Production HTTPS callback and client credentials must be operator-configured; no credentials in repo, images, logs, or browser bundle.
- Sponsored OpenAI inference uses server-side service credentials with existing authorization and spending controls. No personal-key fallback and no real provider calls during this ticket.
- **No DigitalOcean or Cloudflare hosting**; no hosting-platform reconsideration. Use Google Cloud services only where necessary.
- Coordinate only through the human and coordinator. Avoid changes to Gray's launcher/UI and other active work.

## Deliverables
1. Versioned deployment artifacts: Dockerfile(s), pinned dependencies and configuration, startup/restart and health checks; infrastructure configuration or explicit reproducible commands suitable for review. Avoid irreversible defaults.
2. Google Cloud deployment guide covering project/region (Oregon preferred), VM sizing, network/firewall, HTTPS/domain and certificate setup, IAM/service account least privilege, secrets, persistent storage, backup/restore, update and rollback.
3. Transparent monthly and trial-period cost estimate with VM, disk, snapshots, network/egress, external IP, DNS, logs, and any other relevant line items. Distinguish $300 eligible Google Cloud trial credit from OpenAI API billing. Note that trial terms and pricing require operator confirmation.
4. Operator approval gate: explicit checklist and exact proposed resources/commands before any billing activation or provisioning.
5. Local-only deterministic validation of container build, startup, health, persistence/restart, and configuration/security where feasible. Mark unrun checks UNVERIFIED rather than claiming live success.
6. docs/STATUS.md and messages/t42_red_gcp_readiness.txt with MET/UNMET/UNVERIFIED, tests and commands; PR against current main, R4R, no self-merge.

## Acceptance criteria
- Reproducible deployment package runs locally and preserves durable SIGMA state across restarts.
- Google OAuth production configuration is documented but not falsely claimed live-tested.
- Network exposure is minimized; HTTPS and secrets are accounted for.
- Research/SageMath workloads and sponsored inference can be configured without embedding credentials.
- Cost estimate and approval checklist are clear enough for a human to decide whether to activate the trial and provision a VM.
- Run focused checks and ./sigma test; document environment-dependent exceptions.

## Hard stop conditions
Do not activate a trial, enable billing, create or modify Google Cloud resources, run live provider inference, incur charges, or ask for user secrets. Escalate missing architecture decisions, costs, risky migrations, or conflicts to the coordinator through the human.
