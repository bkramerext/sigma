# T34: Polish all release samples

**Status:** Required for final alpha release; discussion pending. **Owner:** Unassigned. **Priority:** Release requirement, scheduled around active worker coordination and integration.

## Objective

Audit and polish **every sample project shipped with SIGMA** so the alpha opens with coherent, credible, attractive examples that demonstrate the real research workflow rather than placeholder content.

## Scope

- Inventory the actual sample catalog and its categories, including imported samples made with `sigma make_sample`.
- For each sample, review title, summary, problem statement, difficulty, strategies, local and testable strategy goals, enabled state, and any included session outcomes and artifacts.
- Ensure examples vary meaningfully in domain and difficulty, with the Riemann Hypothesis correctly framed as an unsolved showcase rather than a proof claim.
- Preserve strategy/session distinctions: durable bounded strategies, attempts in sessions, evidence, failures, revisions, and branches.
- Check sample content for scientific/mathematical accuracy, readable language, plausible next actions, and coherent UI display.
- Ensure no secrets, personal paths, test fixture debris, fabricated discoveries, or misleading verification claims are bundled.
- Validate sample loading, independent editing, export/import, and responsive presentation where relevant; avoid gratuitous UI redesign.
- Decide with the human which examples need realistic, explicitly labeled historical/demo outcomes and which should remain clean starting points. No paid provider calls without explicit approval.

## Acceptance

1. A complete inventory and per-sample pass/fail review exists.
2. Every bundled sample opens successfully, has useful strategies, and is ready to show a new alpha user.
3. Any included sessions/artifacts have correct provenance and clearly labeled verification status; no claim of an RH solution.
4. Sample creation from an exported project is exercised on representative material without altering the source project.
5. Automated checks pass, and relevant sample UI flows are checked in a real browser.
6. Human reviews substantive content/selection decisions before release; submit a scoped PR and do not self-merge.

## Scheduling

This ticket **must be completed before final alpha release**. Plan content review with the human during a coordination gap, while keeping active Codex workers supported and PR integration ahead of documentation polish. Assign implementation only when capacity and dependencies allow.

Every worker-facing assignment must prohibit direct communication or coordination with other Codex workers. Dependencies go through the human and ChatGPT coordinator.
