# T25 — Outcome visual hierarchy and collapsible subsections

**Status:** Proposed; not started. **Authored by:** ChatGPT. **Codex:** Gray proposed (not assigned).  
**Recommended model:** GPT-6 Luna, Medium thinking. Escalate to GPT-6.1 Sol, Medium only if nontrivial cross-component state or accessibility defects arise; do not start at High.

## Intent

Replace the current two-column Outcome presentation with the same established, nested section hierarchy as **STRATEGIES → STRATEGY**. This is a presentation/interaction ticket, separate from T24's data gathering and accounting. Do not implement an Outcome metrics table.

```text
SESSIONS
└── OUTCOME
    General outcome details (currently left column; direct content, not another subsection)
    ▾ STATUS
    ▾ STRATEGY ASSESSMENTS
    ▾ METRICS
    ▾ PROVENANCE
    ▾ EVIDENCE & OBLIGATIONS (only if useful)
```

## Requirements

1. Outcome lives within its owning Session and adopts the visual hierarchy, spacing, borders, typography, chevrons, and disclosure conventions already used by Strategies → Strategy. Do not redesign neighboring surfaces.
2. Keep summary, headline conclusion, primary caveat, and currently left-column general items **directly inside Outcome**, above the subsections. These general items are not a subsection. Remove the old left/right columns.
3. All other Outcome details go under semantically named, individually collapsible subsections. Required: **Status**, **Strategy Assessments**, **Metrics**, **Provenance**. Add **Evidence & Obligations** or another clear subsection only when the data warrants it. Avoid empty and duplicated sections.
4. Status distinguishes run lifecycle/provider failures from research result/verification state. Neither a completed run nor an executed Python program proves a mathematical conclusion.
5. Strategy Assessments retains each strategy's disposition and cited evidence, including the multi-strategy case.
6. Metrics consumes T24's persisted measurements, but displays them as structured label/value rows or compact detail groups **not tables**. Keep operational and research-quality metrics clearly distinguished.
7. Provenance exposes the meaningful source trail (session, strategy, agent role/model/effort if known, cycle, step, artifact IDs, citations, Python execution and captured-file evidence). Reused/interrupted records remain labeled as such. Do not fabricate values or verification.
8. Integrate objections, saved evidence, obligations, uncertainty and other existing Outcome material into appropriate subsections without loss. Preserve previously persisted records and existing report/export behavior.
9. Use the established **Markdown icon/action** wherever Markdown representation is appropriate (e.g. findings, narrative, objections or rationale). It should toggle/open the actual Markdown view with accessible labeling and keyboard activation. Do not add decorative or inert markdown icons on structured status/metric lines.
10. Each subsection must have a sensible default expanded/collapsed state, visible affordance, focus/keyboard/ARIA semantics, and stable behavior when switching sessions, reopening projects, or viewing historic/partial records. Keep screens usable at 320px/mobile and desktop widths. Avoid unnecessary styling changes or excessive empty whitespace.
11. Preserve the current Outcome's source evidence, warnings, navigation and action affordances. Render unavailable fields as not available rather than false zero.

## Acceptance

- Existing Outcome fields can all be found in the revised hierarchy; no lost information.
- General summary is not collapsed into another subsection.
- No metrics table, no residual two-column Outcome grid.
- Independent disclosure interactions and Markdown actions tested with keyboard and pointer.
- Real Chrome desktop and mobile screenshots visually inspected; no horizontal overflow or hierarchy confusion.
- Legacy, stopped, interrupted, completed, and multi-strategy outcomes tested.
- `./sigma test` and focused browser tests pass. No live-provider calls needed.
- Branch from current main, open a PR, do not self-merge, and do not use paid API calls.
