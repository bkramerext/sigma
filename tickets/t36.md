# T36: Clean installation and first-run acceptance

**Status:** Required for final alpha release; unassigned. **Priority:** Release gate, scheduled around active worker support and integration.

## Objective

Prove that a new alpha user can start from a clean checkout and reach a useful first SIGMA session without relying on hidden developer state.

## Scope

- Test the documented installation path on a clean environment or genuinely isolated equivalent, using the release-target revision.
- Verify prerequisites and supported platforms; distinguish required dependencies from optional Docker, Python/Sage sandbox, provider, and cloud capabilities.
- Exercise `./sigma setup`, `./sigma start`, browser launch, first project/sample open, strategy editing, session/report viewing, and graceful shutdown/restart.
- Verify a useful no-account/manual path; separately verify provider connection UX without incurring paid calls unless expressly authorized.
- Check errors and recovery for missing prerequisites, unavailable provider, denied/expired credentials, network failure, and optional sandbox absence as feasible.
- Confirm paths, commands, links, permissions, and environment-variable guidance in README and Getting Started.
- Verify that user data is kept separate from sample/source assets and that no developer secrets or machine-specific paths are bundled.
- Record exact OS/runtime versions, commands, results, reproducible failures, and screenshots where useful. File narrowly scoped corrective tickets for defects.

## Acceptance

1. Documented fresh-checkout setup and launch work on at least one supported environment with reproducible evidence.
2. A first-time user can open a sample or create a project and inspect/use core functionality without private development state.
3. Optional dependencies and provider/billing requirements are explained accurately and fail safely when unavailable.
4. README and setup instructions are reconciled with observed behavior.
5. Final acceptance evidence is included in T35 release sign-off; unresolved failures are explicitly classified as blockers or accepted limitations.

## Scheduling

Required before final alpha release. Coordinate with T31 README and T34 samples; do not displace active Codex support, PR reviews, or integration. Do not run paid provider calls without explicit human authorization.
