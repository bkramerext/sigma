# T28 — Computational evidence and artifact comprehension

**Owner:** Green. **Status:** Implemented on `feature/t28-computational-evidence`; PR open. **Priority:** Complete for review.
**Recommended model:** Luna Medium.

## Goal
Close the computational-evidence gaps from Green's T19 report without creating a new execution subsystem.

## Scope
- Let authorized research agents inspect meaningful content of captured plots and binary artifacts, not just filenames or metadata. Use bounded, safe representations with explicit truncation and unsupported-format notices.
- Enable accurate cross-session synthesis of prior Python computations, inputs, outputs, plots, limitations and provenance. Avoid silently treating reused or failed computations as new evidence.
- Validate and improve execution-tool guidance where needed, in coordination with Blue's T27 agent prompts and Green's T26 SageMath support.
- Preserve isolation, artifact limits, budgets, truthful failure states, existing reports and persisted records. No unbounded model/image calls.

## Acceptance
- Deterministic tests for representative plots/artifacts, corrupt or oversized files, missing formats and provenance.
- A multi-session scenario where a later agent can inspect and cite an earlier computation correctly, including uncertainty and execution status.
- Regression tests for Python and SageMath when available; `./sigma test` and container checks where applicable.
- Document security/size limits and unverified live-provider behavior. Open a PR for review; no self-merge.

## Dependencies
T19/T24 and T26 are merged. T27 (PR #18) merged while T28 was in progress; the T28 branch includes the latest main history. No new execution subsystem or UI changes are part of this implementation.
