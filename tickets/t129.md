# T129 — Release-image SHA correctness and reproducibility

**Owner:** Gray
**Status:** R4R; offline implementation only. Hosted release acceptance remains unverified.
**Base:** current `main`; PR targets `main`.
**PR:** [#182](https://github.com/bkramerext/sigma/pull/182) · [handoff](../messages/t129_gray_release_sha.txt)

## Objective
Build and run the exact Git commit requested by the release operator, fail closed if it cannot be resolved, and record actual source commit and image digests.

## Scope and acceptance
- Trace and correct the release build/deploy/rollback path without changing deployment architecture.
- Ignore dirty/unrelated checkout contents by exporting the requested full commit SHA as the build context.
- Reject missing, malformed, or unresolved commits before building; verify image source labels match the requested SHA before startup.
- Prevent production Compose from building from the live checkout during startup.
- Record source SHA, immutable image IDs and available registry digests after successful Compose startup.
- Add deterministic tests for dirty worktree, unrelated HEAD, unresolved/mislabeled requested SHA.
- No live cloud operations or deployment; no paid providers.

Hosted deployment acceptance remains outside this ticket and is not claimed.
