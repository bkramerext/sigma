# T22.2 — Google authentication and invited access

**Owner:** Red. **Status:** Ready for review. **Parent:** [T22](t22.md); follows the
merged Cloudflare feasibility work in T22.1.

## Goal

Add an explicitly enabled Google OpenID Connect sign-in path for hosted SIGMA,
with server-side authorization and a small administrator Access Management UI.
Preserve the existing local, single-user experience and ChatGPT authorization.

## Scope

- Verify Google ID-token signatures and required issuer, exact audience,
  expiration, nonce, subject, and verified email claims.
- Authorize only exact active email invitations, exact verified email domains,
  or the configured bootstrap administrator. Email revocation overrides domain
  allow rules and invalidates sessions promptly.
- Store one-use OAuth flows, hashed opaque sessions, authorization entries, and
  change audit records in a private SQLite database outside project data.
- Protect every API endpoint by default in cloud mode; keep only status,
  readiness, login, and callback public. Require exact Origin for mutations.
- Provide copper/dark Access Management controls for email/domain invitations
  and revocation. Invitations send no email.
- Default cloud auth to disabled. Keep Google identity separate from provider
  authorization and billing; do not change existing local ChatGPT authentication.
- Integrate Google sign-in and authenticated account controls into the existing
  copper/dark Home/header above the project area. Do not show the legacy Google
  sign-in placeholder or introduce a parallel account bar. Keep local mode
  unrestricted and independent from the cloud identity gate.
- After verified but unauthorized sign-in, show an “Access not yet granted”
  screen with Explore Demo, Request Invitation (`mailto:` to configured admin
  contact; no delivery), and Use Another Account. Retain the verified email only
  in a short-lived denied-access record for this experience, display it there,
  and prefill it into the request. Do not create a session/workspace or reveal
  access rules. Use Another Account clears this denied state and starts fresh
  Google account selection.
- Coordinate Explore Demo to the parent T22 public guest route `/demo` without
  provisioning a private workspace. This ticket provides only the no-workspace
  navigation handoff; the curated Demo data/view, guest API restrictions and
  exports remain parent T22 work.

## Explicit boundaries

No workspace migration or per-user project storage isolation, curated Demo data,
guest-safe project/session/report API, durable job scheduler, cloud deployment,
or hosted AI-provider authorization. The auth gate controls who may enter the
existing API; it does not make shared filesystem paths tenant-private. The
`/demo` navigation handoff must not create a project or private workspace. See
[cloud auth configuration and boundary](../docs/CLOUD-AUTH.md).

## Acceptance

- Authorized Google identities receive a server-side session; unlisted verified
  identities receive no session and see “Access not yet granted.”
- Cloud sign-in/account actions appear in the existing Home/header; the legacy
  Google placeholder is absent. Local mode retains unrestricted project and AI
  APIs without requiring cloud auth configuration or a Google identity.
- The denied screen offers Explore Demo (`/demo`, no workspace creation),
  displays only that attempt's verified email, and offers Request Invitation
  (prefilled `mailto:` to `SIGMA_CLOUD_ADMIN_CONTACT_EMAIL`, including the
  verified email) and Use Another Account (which clears denial state and starts
  fresh Google account selection). No session/workspace is created.
- The status and denial response never return allowlist entries, allowed domains,
  or other users. Every private API continues to reject unauthorized identities.
- `/demo` remains a handoff only. T22 retains ownership of the public curated,
  read-only Demo and guest API enforcement; no full Demo is included here.

## Verification

Deterministic no-network tests cover successful and unauthorized sign-in,
signature/claim failures, exact domains, invitations/revocation, session
expiration, denied-account redirect/cookie clearing, configured invitation
mailto behavior, API protection, and local-mode compatibility. Run `./sigma test`
and real-browser desktop/mobile checks. No paid provider calls.
