# T192 — Per-User Project Isolation

**Status:** Implemented; PR open for review  
**Base:** `main`  
**Scope:** Audit and close server-side workspace isolation gaps across authenticated Google users.

## Acceptance and findings

- Workspace ownership is derived from `Principal.subject`, populated after Google OIDC signature, issuer, audience, nonce, expiry, and authorization checks. The durable workspace mapping hashes that subject; request identity and workspace headers do not select ownership.
- A protected-route dependency binds the verified principal to a durable workspace for each request. Project path resolution rejects traversal, symlinks, and paths outside that workspace. Local mode keeps its existing project root and Recents behavior.
- Existing adversarial integration tests cover project IDs/paths, strategies, sessions, evidence, reports, papers/downloads, exports, research executions/artifacts, forged headers, traversal, symlinks, guessed IDs, account separation, restart, and full-root backup/restore.
- This ticket adds cross-owner mutation regressions for project updates, text-source evidence, and execution creation. Rejections are asserted before any victim project, execution-record, or evidence-source mutation.
- Research Python/Sage containers have no project/workspace mount, no network, read-only root, and fixed unprivileged settings; command assertions and project artifact API ownership checks remain in the existing sandbox suite.
