# T47 — First-class Markdown Conclusion in Research Session Outcome

**Priority:** High
**Owner:** Gray
**Status:** R4R · [PR #72](https://github.com/bkramerext/sigma/pull/72)
**Base:** Current main; dedicated branch/PR

## Objective
Place a prominent **Conclusion** section first within the existing Research Session Outcome. It is a persisted, Markdown-renderable answer to the project description *to the extent supported by that session*, not a claim that every strategy or session solves the project.

## Scope
- Use existing Outcome collapse/expand visual language and existing Markdown action button behavior. Conclusion expanded by default; other details remain available below. Preserve existing copper/black design and mobile/keyboard behavior.
- Generate/persist coherent Markdown from reviewed session findings, across multiple strategies when present. Distinguish established findings, conditional findings, failures, and open obligations. Never manufacture completeness, proof verification, or evidence.
- Existing research evidence, structured reasoning steps, Skeptic objections and source references remain authoritative and accessible. Conclusion is an entry point, not a replacement.
- Reports and TeX paper generation should be able to consume the persisted Conclusion alongside *all underlying evidence*. Coordinate integration dependencies through the human/coordinator. Do not rewrite Blue's active PR #68 or Red's active PR #70; identify needed interface and downstream follow-up.
- Legacy sessions without a persisted Conclusion should display an honest fallback; do not fabricate historical answers.
- T46 About ticket separately contains the approved product message: **Strategies propose. Sessions investigate. Outcomes answer. Reports communicate.** Ensure About never describes an unmerged feature as shipped.

## Acceptance
- Markdown supports headings, paragraphs, math and lists consistent with existing renderer; Markdown action exposes usable Markdown.
- Session with successful mathematical derivation displays a bounded coherent answer with conditions and agent-reviewed/unverified status; a partial/failed session prominently states its limits.
- Multi-strategy session synthesizes supported collective findings without claiming a failed branch disproves the entire project.
- Persistence/reload/export behavior tested; source evidence is not dropped; long text does not silently truncate into unsupported claims.
- Real-Chrome desktop/narrow-width interaction and accessibility checks; focused deterministic tests and `./sigma test`. No live or paid provider calls.
- R4R PR, message file under `messages/`, and explicit unresolved integration dependencies. No self-merge.
