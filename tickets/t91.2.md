# T91.2: Packaged PDF and disaster-recovery acceptance

**Owner:** Gray  
**Base:** current `main`; ticket branch targets `main`  
**Type:** focused pre-cloud acceptance; no new feature initiative

## Objective

Verify production-packaged SIGMA can compile saved TeX with its actual Tectonic
binary, persist and serve the resulting PDF and associated research records,
and recover a meaningful private workspace from backup into fresh storage.

## Acceptance

1. Build/run the packaged backend. Compile valid saved TeX with the packaged
   Tectonic executable, inspect the resulting PDF's structure/content, and
   download the saved artifact through the authenticated API.
2. Verify saved TeX, PDF, reports, project/strategy identities, sessions,
   outcomes and evidence survive backend container recreation.
3. Back up durable storage, restore it into a new disposable storage volume,
   and verify owner mapping, content, identities, and artifact hashes.
4. Verify a second simulated authenticated user cannot retrieve the restored
   owner's project, PDF, report or session evidence.
5. Verify malformed TeX returns an explicit compilation failure and publishes
   no partial/corrupt PDF. Failed restore setup must exit unsuccessfully.

## Constraints

- Use deterministic research/report fixtures; no paid inference, real Google
  OAuth exchange, or GCP resources.
- Red owns host bootstrap, rootless Docker, disk mount and systemd. Blue owns
  inference accounting. Green owns UI. Do not change or repeat their acceptance.
- Keep changes limited to acceptance/regressions and consequential evidence.
- Run the full `./sigma test` suite and relevant packaged real-browser checks.
- Record actual PASS/FAIL/BLOCKED results, commands, elapsed time, commit SHA,
  and cloud-only limitations. Open a focused PR; do not self-merge.
