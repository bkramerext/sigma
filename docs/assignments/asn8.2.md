## Product objective and non-negotiable design direction

**SIGMA should feel like a research tool, not an API configuration console.** Ordinary first use:

1. Run **`./sigma ui`**; no account, API key, `.env`, or provider feature flag is required to open SIGMA, create/open projects, or write strategies.
2. A small interactive **Connect AI** affordance is visible in the **upper-right corner**, in the position occupied by the current status dot, both on Home and in the project workspace. **Do not** introduce a third prominent Home action beside Open Project and New Project. Preserve all approved Home artwork, A5/A7 branding and workspace layouts byte-for-byte.
3. Click **Connect AI** → **Continue with ChatGPT**. Complete browser-based Sign in with ChatGPT once; eligible AI requests use the account's ChatGPT plan allowance/credits, **not a new per-token API bill**.
4. After connection, the corner reads something like **ChatGPT connected** (small green status dot + readable text). The control opens a concise account/settings popover: active ChatGPT account (where available), **Using ChatGPT plan**, Manage usage, Switch account/Connect another account, Disconnect, and an **advanced, explicitly selected API-key option**.
5. Someone may ignore connection indefinitely and work manually. If they later press **Generate with AI** while disconnected, begin the same ChatGPT sign-in there, **without navigating Home, discarding the seed idea, losing the draft or requiring re-entry**. On successful sign-in, continue the initiating generation workflow once, honoring cancellation; don't start extra requests just for having signed in.
6. On later launches, silently recover the saved, authorized session using standard token refresh. If reauthorization is necessary, show **Reconnect ChatGPT** as an action, not a fatal startup error.

**Human guidance:** “Don't add gates until we understand why we need them.” Remove arbitrary configuration and repeated pre-generation prompts. Keep only controls that fulfill a demonstrable purpose: provider OAuth authorization, an explicit human click to generate, clear separation of plan allowance versus individually billed API mode, honest errors, and an explicit human acceptance step before any strategy is persisted. Do **not** introduce a first-launch sign-in blocker, custom spending cap, forced provider setup, a new `SIGMA_AI_ENABLED` gate, or a per-request consent checkbox. The official UI guidelines ask for a **one-time, dismissible explanation** after successful ChatGPT-plan sign-in; this is informational and must not become another recurring gate.

**Terminology:** An OpenAI API key and a ChatGPT sign-in are different credential/billing paths. Never claim that `/v1/models` alone proves billing access or a particular model's inference entitlement. Never claim ChatGPT Plus offers unlimited capacity. ChatGPT-plan usage is subject to eligibility, account/workspace policy and plan/app limits; the local API-key option uses separate API billing.

## 1. Connection UI: one interactive header control, always secondary

**Reuse/rework the existing A8 upper-right status indicator** on both Home and the workspace:

- **No provider configured:** neutral small dot + **Connect AI**. Clicking opens a popover (or similarly compact accessible anchored surface) whose main action is the officially branded **Continue with ChatGPT**; an unobtrusive **Use API key (advanced)** option is available, not a peer to Open Project/New Project.
- **Authorization pending:** spinner or neutral status + **Connecting…**; no false green. Explain browser handoff if needed; cancel closes that specific attempt without clearing any previously active valid account.
- **ChatGPT authorized and permitted for plan usage:** green dot + **ChatGPT connected**. Popover shows verified account label/identity when available, **Using ChatGPT plan**, **Manage usage**, Switch/Connect another account, Disconnect, and optional choice of API-key mode. **Green means a validated, usable session and required granted scopes**, not that a generated response or unbounded usage is guaranteed.
- **Signed in but plan-use scope declined/not granted:** **ChatGPT connected · plan access not enabled** or a clearer non-green state. Offer **Enable ChatGPT plan use** (reauthorize with needed scopes) or the advanced key option. A valid identity token alone does not enable inference.
- **Expired/revoked/needs interactive sign-in:** **Reconnect ChatGPT**, with explanatory popover and retained project context; don't attribute these to a missing API key.
- **Provider outage or unknown access:** subdued warning status with Retry; do not sign the user out, fabricate green status, or start a paid request as a health check.
- **ChatGPT usage limit reached:** clear, non-scolding text and **Manage usage** as the primary recovery action. Keep plan mode selected; **do not** automatically charge the saved API key. Display actual provider limits if known, never invent a remaining-token meter.
- **Explicit API-key billing mode:** header label such as **OpenAI API · key billing** plus real verified authentication status, with clear provider mode in the model picker and near generation. Do not label key-authenticated use “ChatGPT connected.”

Apply keyboard activation, Escape/outside closing, focus restoration, accessible button/text status (not color alone), proper contrast, meaningful live announcements without noise, readable MacBook and 320/390px layouts. Avoid repeated animations, giant sign-in modals, competing page CTAs, or new artwork. Keep the connection control near the top right on project and Home pages. Follow approved OpenAI branding rules rather than drawing a counterfeit sign-in logo.

After **first** successful plan-use authorization show the documented *one-time*, lightweight “You're using your ChatGPT plan” confirmation with **Got it** and a path to Manage usage; never on every restart or reconnect. Be precise that eligible AI use consumes **plan allowance or credits**. Do not claim it is free/unlimited or that sign-in grants access to ChatGPT conversation history.

## 2. “Generate with AI” should connect on demand and resume

- **Manual strategy creation** must never need any AI connection.
- The existing Generate with AI dialog has an optional Starting point/seed and an editable human-review draft. If disconnected, **preserve in-memory form state** and start ChatGPT sign-in from that exact place; on return, re-open/resume the same dialog, not an unrelated modal or a Home redirect.
- Because the user deliberately clicked Generate, once authentication succeeds **resume that one pending generation** (not an additional speculative request). If the user only clicked the header's Connect AI control, do **not** generate anything. If authentication fails, is declined, or gets cancelled, retain the seed and show Retry/Continue manually without submitting a provider request.
- A cancel, project change, duplicate callback, second click, browser back, or lost session must not produce duplicate generation or save. Reject stale pending intents (e.g. changed project identity) safely rather than sending another project's data; keep editable text if possible. Explicit Regenerate remains another intentional request.
- No separate `consent: true` checkbox or gating message for ChatGPT-plan generation; replace it with a concise evergreen privacy/usage explanation near the feature as useful. **Keep user approval to save** the generated strategy, A7 integrity/duplicate checks, receipts and actual model/effort provenance. Do not save a generated strategy on login or on response completion without Save Strategy.
- When generating, show a small contextual **Using ChatGPT plan** or **OpenAI API · billed separately** label and the selected model/Thinking level. **Do not silently switch billing paths** on error, exhausted plan allowance, inability to refresh or model unavailability.
- The user may explicitly choose the API-key path in the connection popover; make mode/account choice an **application/session preference**, not hidden in individual project JSON. Project JSON continues to store research settings (model, effort, mode etc.), not credentials/tokens. Don't silently rewrite existing project model IDs when provider context changes.

## 3. Implement documented local OSS OAuth, correctly and securely

- **Stable `ext_agent_host_id` per installation host**, generated once before first sign-in and preserved across restarts/checkout upgrades. Use the documented opaque `urn:uuid:<UUIDv4>` alternative or recommended JWK thumbprint (document the choice). Do not use email/user identity, create a new host per start or conflate host ID with project UUID or A8.1 launch instance ID.
- First-time dynamic client registration uses **`client_id=dynamic_agent_client`**, `agent_name_hint=SIGMA`, the stable host ID, and the specified scopes: `openid profile email offline_access resource.invoke chatgpt.tokens.use.direct`, `resource=https://api.openai.com/v1`. Persist the returned **issued client ID** for the verified account/workspace; never attempt to exchange a code with `dynamic_agent_client`.
- Each attempt uses a fresh cryptographically random **state, nonce and PKCE S256** challenge/verifier, and the **loopback** `http://127.0.0.1:<port>/auth/callback` exact redirect URI (may choose available port). Start the local callback listener before opening the system browser. Validate state, callback errors, issued client-ID binding, PKCE exchange and OIDC ID-token signature/JWKS, issuer, audience, expiry, nonce, subject and granted permission scopes before activating a session. Use standard packages where appropriate; no home-grown JWT signature shortcuts.
- OAuth authorization code exchange occurs through the documented OpenAI token endpoint without a client secret. Validate the actual token response; keep authorization attempts bounded/time-limited and single-use. Returning sign-in and refreshing use the saved issued client ID, bound verified account and host ID, not a new anonymous registration. Preserve old active connection until replacement is confirmed valid.
- Protect credentials at rest in **OS credential storage (e.g. macOS Keychain)** when practical, or an explicitly justified local 0600, no-follow, owned credential file inside an owned 0700 state dir. Store access/refresh/ID tokens and client mappings **outside `projects/*.sigma`, `.env`, git, frontend localStorage, URLs, logs, or browser-visible API payloads**. Honor the document's supported storage format. Don't re-use A8.1's ephemeral per-launch ownership token as OAuth host identity.
- Access tokens expire; refresh and persist rotated refresh tokens **atomically and serially**, with correct `earliest_refresh_at` behavior; tests include races, restart/reuse, failure handling. Documented remote revoke on Disconnect; if revocation cannot be confirmed, disclose this and clear local secrets per provider guidance, rather than claiming remote revocation succeeded.
- Support at least one ChatGPT account well, while storing registrations separately and offering **Switch account / Connect another account** as documented; never merge registrations by email alone or substitute credentials across accounts/workspaces. Keep an active account selected explicitly.
- SIGMA remains a **localhost-only** program, with A8.1's safe restart and strict allowed-host/origin rules intact. Callback endpoints and auth-state mutations must defend against cross-origin requests, CSRF/callback injection, open redirects and accidental exposure of tokens to the frontend. Return minimal safe UI status/account labels, not raw OAuth payloads.
- Do not obtain ChatGPT-plan credentials by reading any other app's local login files or by asking users to paste tokens.

## 4. Real account-specific model catalog and API integration

**Two auth modes require different catalog and request handling.** Refactor behind a small backend provider/session adapter instead of scattering `OPENAI_API_KEY` references:

**ChatGPT-plan OAuth:**
- Query `GET https://api.openai.com/v1/models` using the **active OAuth access token**. The published direct-route format contains **`models`** entries with `slug`, `display_name`, `visibility`; filter to displayable/compatible models and preserve the provider ordering where useful. This is **not** the API-key `data[].id` response.
- Continue the A8 principle of **curated research-capable models** and selected model/Thinking compatibility, but intersect with the actual active account's catalog; do not assume API-key availability implies plan availability. Respect provider-specific model identifiers even where one name maps differently. Keep saved unavailable project selection with a truthful warning and an intentional change action; do not auto-switch to a different model or downgrade High.
- Requests to `POST https://api.openai.com/v1/responses` must use **`store: false` and `stream: true`**, **`input` as an array**, `instructions`/documented developer messages, and **omit current preview-disallowed fields** (including A8's present `max_output_tokens`, and `previous_response_id`; don't send unsupported explicit system-role message objects). Follow https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations exactly. `reasoning.effort` may be used only where the chosen account/model supports it. Retain bounds via deadline, maximum streamed bytes/events, cancellation and response validation rather than a forbidden request field.
- Parse actual **SSE response events through `response.completed`**; handle `response.failed`, `response.incomplete`, refusals, disconnect, non-200 direct-route admission and malformed/out-of-order events. No free-floating assumption of a single JSON response body, no unbounded stream, automatic retries or speculative inference. Keep the existing one-proposal strict structured fields and validation. Verify the selected plan route accepts the chosen **`text.format` strict JSON schema** and reasoning pair using documented support and controlled provider fixtures; if incompatible, report the concrete capability limitation and keep manual strategy available, never fake a generated response. Do not run paid tests or consume the user's plan without their explicit permission.
- Sign-in and model listing are **non-generating operations**. Don't claim model-list success proves the subscription's remaining allowance, model inference or structured-output support. A real completed authorized inference is the ultimate check.

**API-key mode (optional advanced):**
- Preserve A7/A8's working key-based Responses endpoint and **`data[].id`** model listing, project model+effort validation, non-streaming option if supported, and existing verified-status classification. **Remove `SIGMA_AI_ENABLED` entirely** as a runtime requirement: a configured API key plus the user's **explicit selection of API-key billing mode** suffices. A key in `.env` is allowed for compatibility but **never required** to launch SIGMA, authenticate through ChatGPT, or perform ChatGPT-plan inference.
- Existing A8.1 `.env` loading remains a convenience for the optional key mode; do not weaken its safe parse/env precedence or restart behavior. An API key must never be silently used because ChatGPT-plan auth fails or hits a limit. Indicate the billing mode beside Generate and in the connection popover.
- Avoid an unnecessary per-request consent checkbox in either mode; pressing Generate is an intentional request, and the interface has already plainly identified the provider and billing mode. Keep the user's explicit **Save Strategy** to persist. If a privacy disclosure has changed significantly, use concise permanent copy rather than forcing a recurring gate.

## 5. Minimal, safe backend/frontend contracts

Choose concrete routes after inspecting current `src/sigma/api.py` and `/api/ai/*`. The frontend should be able to:

- Fetch a **unified sanitized connection state** with provider mode, status (`disconnected | connecting | connected | reauth_required | plan_not_permitted | usage_limited | unavailable` or equivalent), verified account label, last check and actionable next step, never token fields.
- Begin/cancel a **stateful sign-in attempt** and receive only an opaque transaction identifier/status and the known trusted authorization URL (no secret verifier or auth code in React). Finish via the secure 127.0.0.1 callback and safely resume the initiating Generate action.
- Explicitly select/review **ChatGPT-plan mode** vs **API-key billing**, switch ChatGPT accounts, retry, manage usage, disconnect/revoke and query a **mode-aware catalog**. If an authorization URL is opened via the browser, enforce correct origins and link target checks.
- Keep backend ownership of all HTTP calls to OpenAI, tokens, refreshing and model-compatibility decisions; never put bearer tokens or API keys in `VITE_` environment variables or React storage.
- Preserve A8's project schema v6, stable UUID, model and High default, and no-write-on-close convention. Do not require a schema upgrade solely to support OAuth. If recording **auth mode in AI provenance** is necessary to explain an artifact, version/migrate explicitly and retain earlier records; never overwrite earlier provenance or conflate model access paths.
- UI state must survive route transitions and in-progress auth without a full project restart; preserve pending seed/draft and avoid reconnect redirects that lose user state. Respect browser-only localhost security, existing CORS and referrer checks, and A8.1 port ownership rules.

## 6. Failure handling: no imaginary paywall, no silent billing or fake readiness

- Declined login, user cancellation, no `chatgpt.tokens.use.direct` grant, invalid state/nonce/JWT, mismatched account/workspace, expired tokens, refresh-token reuse/rotation errors, revoked consent, 401/403/429 and 5xx must show **different truthful next steps**, without raw provider secret/body leaks.
- When the plan or app usage limit is reached, **Manage usage** goes to the *documented* ChatGPT usage settings URL. Don't invent a plan quota or present it as an API-key billing error. No silent API-key fallback, not even if a valid key exists on the machine.
- If the user selects API-key mode and the key is absent or invalid, say **API key not configured / not authorized** with an advanced setup hint, not “ChatGPT disconnected.” If OAuth is authorized but not permitted for plan usage, don't mark inference “Ready.”
- Keep offline manual research fully operational in every state. Authentication health calls must not create project writes or auto-start jobs.
- Avoid duplicate prompts and spinners: the connection popover is the one account control; on-demand sign-in plugs into the existing proposal flow. Never ask to connect before Open/New Project, or show a billing decision on every request once the mode is explicitly selected.

## Acceptance criteria

A new installation needs **no API key, no `.env` file and no enable switch** to launch or create research projects. SIGMA offers one unobtrusive **Connect AI** control in its existing top-right area, an official **Continue with ChatGPT** sign-in, secure remembered/refreshable authorization, a meaningful ChatGPT-plan connection state, and **connect-on-demand during Generate** without losing the seed or duplicating work. Authenticated plan-mode requests use the documented streaming Responses contract, not key-mode assumptions. Separate API-key billing remains an optional explicitly chosen alternative. **Never automatically switch a user's usage from ChatGPT-plan allowance to paid API calls.** No fake agent runner, unrelated project schema changes, extra approval screens, or visual redesign.
