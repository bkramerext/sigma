## Increment 8: carry a bounded, sourced question across sessions

**Problem observed:** Increment 7's saved graph follow-up contained a specific Skeptic `next_question`, but a new same-strategy session reset to generic “Advance this strategy...” wording. Under the existing `coordinate_decision`, budget exhaustion deliberately clears the artifact's active `next_question`, even though the original Skeptic's proposed next question is retained in `skeptic_output.next_question`. An unscripted role might recover it from the prior finding index, but that choice has not been observed.

**Change:** `src/sigma/research_sessions.py` now selects the latest *eligible* per-strategy, terminal saved artifact when starting a new session. It reuses `artifact.next_question` where still actionable, or the original Skeptic proposal after budget exhaustion. The proposal must be in the frozen, strategy-scoped prior finding index. A newer ineligible terminal artifact blocks fallback to stale older suggestions. The source carries its session/artifact/strategy IDs, exact source field and `model_suggested_unverified` qualifier. This is **a question, not evidence, approval, verification or proof**. It appears as `initial_question_source` in the immutable session snapshot and `question_source` in first-cycle role dispatch, while later cycles can change the active question without making the initial provenance stale. Explicit researcher-approved continuations take precedence. No original session is edited.

**Adversarial controls:** `tests/research_sessions.py` exercises (a) newer-vs-older and missing/foreign source rejection; (b) retracted, decisive-counterexample, productive-conclusion and no-progress exclusions; (c) a real saved two-role offline session whose budget ends with a nonempty Skeptic question but empty artifact active question; (d) next multi-strategy session with scoped carry and unrelated history inquiry retaining its generic question; (e) actual first Investigator HTTP context containing the exact question and source IDs; (f) prior session byte-for-byte immutability and researcher-approval precedence. Model roles are deterministic fixtures. This is domain-general logic; no graph/parity answer strings or benchmark-specific hooks are used.

## Increment 9: provenance before authored conclusions

**Observed gap:** A saved Conclusion and exported report put fluent agent-authored claims before the saved execution ledger. A graph-withheld control from Increment 7 demonstrated the hazard: an authored Conclusion could imply computational support even when no code executed. This is a **presentation/provenance gap**, not evidence that a model's text can be reliably classified by keywords.

**Implementation:** A read-only `execution_provenance(record)` inventory derives execution IDs, runtimes, statuses, owning artifact/step IDs, source presence and output presence from saved Investigator artifacts, provider steps and pending branch executions. It deduplicates repeated references to one execution and refuses to count conflicting saved statuses as completed. Missing execution IDs remain explicit. It neither interprets the program output nor asserts that a successful run verifies an authored claim. `_outcome` exposes this inventory without rewriting historical sessions. The existing Simple and Advanced Outcome UI now displays the recorded-computation prelude *before* the authored Conclusion. TXT, HTML and TeX project reports render the same provenance inventory before the narrative, with a clear zero-record statement when no execution was persisted. Authored conclusions are preserved verbatim; noncomputational reasoning remains available, not automatically downgraded.

**Adversarial controls:** `tests/project_reports.py` checks a falsely confident model-authored measurement claim with zero persisted executions, ordering across TXT/HTML/TeX, one successful Python execution referenced twice (deduplicated), a timed-out SageMath execution, inconsistent statuses for one ID, and an unidentified execution. `tests/research_sessions.py` checks derived Outcome provenance and source-record immutability. These are synthetic records and scripted controls, **not** autonomous model research. No stock sample was modified.

## Increment 10: material source readiness and assumptions

**Observed boundary:** Prior finding contexts recorded truncation, saved steps, retraction and assumption notes, but later agents lacked a concise provenance-derived statement distinguishing available material from reviewed premises. The automatic saved next-question selector only checked whether an artifact ID was supplied. A shortened assumption field could therefore accompany a carried full-text question without flagging the missing scope.

**Change:** A small deterministic `source_readiness` projection is attached to current-session compact artifact extracts and bounded prior-session findings. It distinguishes withdrawn, incomplete, model-reviewed-steps, unresolved-steps and narrative-only extracts, and separately marks whether declared assumptions were covered by *model-reported* review. `original_in_context=false` and `independently_verified=false` are explicit. The projection is not a truth/entailment checker and never certifies science, mathematics, history, or strategy claims. The saved follow-up selection now declines an automatic question when its supplied extract truncated assumptions, evidence status, or the question itself. Truncated derivation steps alone do not veto proposing a bounded next test; they still cannot serve as full cited proof.

**Controls:** Added direct adversarial tests for model-reviewed assumptions, incompatible reviews, withdrawn and truncated material, noncomputational narrative, unresolved steps, and valid-versus-truncated question continuation. Existing real persisted role-dispatch regression now inspects the actual source-readiness flags; its prior session bytes remain unchanged. No sample-specific strings, answer keys, or inference from file names enter the implementation.

**Assessment:** **MET at implementation/test scope**, subject to the current cumulative PR-head CI check. **UNVERIFIED:** semantic compatibility of assumptions, correct model review, usefulness of carrying this question, and whether readers or autonomous roles act on the warning. String normalization only compares declarations and review labels. A favorable label remains model-reported, not independent evidence.

## Increment 11: cross-domain actual dispatch controls (offline roles)

**Change:** A new regression creates four separate real persisted SIGMA projects and runs the usual saved-session creation, Investigator/Skeptic HTTP dispatch through a deterministic local transport, end-of-budget record, next same-strategy session, exact first Investigator request, and cancellation of its blocked mocked response. It checks that the proposed next question survives with the exact source artifact, that model-reviewed premise metadata stays unverified, that the selected strategy is correctly attributed, and that the original session bytes do not change.

| Domain | Bounded problem and distinct evidentiary need |
| --- | --- |
| Biology | Reagent/growth hypothesis, randomization and batch-confound control |
| Historical source criticism (Other/default) | Conflicting archive accounts, custody and dating before reconciliation |
| Fictional logistics scenario (Military) | A plan subject to capacity constraints and a changed resource budget |
| Mathematics | Finite pattern, restricted scope, next unsampled case rather than universal proof |

This is deliberately **not** four demonstrations of research ability. The offline roles return evaluator-scripted assertions and next questions; real provider judgment, search strategy choice, mathematical understanding, experimental validity, and source interpretation are not exercised. The project/session machinery, source provenance, persistence and dispatched request bodies are real. The temporary project files created inside CI are cleaned up; no new independently archived project export is claimed. The same generic logic is used for all four domains, without domain-specific code branches or benchmark answer strings.

**Assessment:** **MET at exercised engineering scope**, subject to exact-head CI. **UNVERIFIED:** autonomous domain transfer, sensitivity to a genuinely conflicting source, ability to propose an effective experiment, and comparison against a single-role baseline. The existing cross-strategy tests address isolation separately; these new tests are primarily about same-strategy temporal continuity.
