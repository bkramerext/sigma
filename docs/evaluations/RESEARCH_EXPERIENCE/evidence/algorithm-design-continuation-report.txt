Design and Verify an Incremental Dependency Scheduler v1
========================================================

Project
-------
Interpretation: Agent-generated findings are provisional unless explicitly verified; reviewer agreement is not proof.

Research problem: Design an algorithm for a build system that maintains a directed dependency graph under edge additions and removals, answers whether the graph contains a cycle, and, when acyclic, produces a valid build order. Assume up to 100,000 vertices and 1,000,000 edges, with long sequences of updates and queries. Specify exact semantics for updates, including duplicate edges and nonexistent removals, data structures, pseudocode, correctness invariants and proofs, time and space complexity, and adversarial tests. Compare at least two approaches, including a straightforward recomputation baseline. Seek useful incremental performance without asserting an unproved bound. If worst-case efficient fully dynamic maintenance is not established, distinguish a correct implementable solution from a proposed optimization and give a discriminating benchmark.

Strategies
----------
Baseline before incremental claims (saved)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Define duplicate insertion and missing deletion as idempotent operations. Maintain adjacency sets; recompute a topological order with Kahn's algorithm on queries and return a cycle witness when it fails. Prove the invariant before measuring. Compare chain, fan-out, repeated back-edge insertion/deletion and disconnected updates. Record update/query mix and include full-order output cost. Evaluator-authored plan; no benchmark has run.
