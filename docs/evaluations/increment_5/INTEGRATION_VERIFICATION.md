## Data and limits

Actual before/after Project Audit JSON, browser-final audits after Preferences changes, current-understanding JSON, native TXT/HTML/TeX reports, execution-service JSON and downloaded observation artifacts are in [exports](exports/MANIFEST.md). The browser-final audits differ in project Preferences/history but have research-session objects equal to the post-session audits. The original stock sample and retained pre-Increment-5 sessions were not rewritten. Earlier local development smoke exports were preserved outside the repository at `/tmp/sigma-blue-increment5-earlier-smoke-09Zc82/`; the committed export set is the final `1acb310` API run. Absolute scratch paths in the manifest are provenance, not a dependency for reviewing committed exports.

The scripted provider intentionally read actual output and chose the next question; it cannot establish autonomous Investigator or Skeptic comprehension. Hash/citation checks establish observation identity, not the truth of an interpretation. Full-literal dispatch avoids an untested alias-comprehension risk at a measured byte cost. The first mobile evidence view is still a long JSON disclosure; it is inspectable and does not overflow, but it is not a pleasant way to understand a computation. Native Markdown project reports, PDF/AI papers, live latency/cost and unscripted model comparison remain untested.

**Would I continue researching here? Maybe.** The integrated workflow now preserves a defensible line from a bounded question through computation, objections, continuation, Outcome and export, and the Simple view is more navigable. I would use it for controlled investigations and careful evidence review. I would not yet trust it to decide what is true or to outperform a simpler research assistant without the [blind evaluation](BLIND_RESEARCH_GATE.md).
