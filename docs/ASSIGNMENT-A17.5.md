## Feature: combined Project export dialog

- Replace the existing Project Download control and the proposed separate Report control with **one Report Artifact icon button** in the Project title actions beside Settings. Provide accessible label, keyboard focus and native hover title. Use a document/text icon (for example, file-text) rather than a download icon: the action creates an artifact that may be downloaded or opened in a browser, so a document better represents both behaviors.
- The **Report Artifact** dialog offers **Export type** radio buttons: **Project Audit** (selected by default) and **Research Report**. Project Audit must preserve the existing JSON audit export content and semantics.
- Show a **Format** dropdown at all times, with a compact width appropriate to its short options rather than stretching across the dialog. For **Project Audit**, the dropdown displays **JSON (.json)** and is disabled/non-changeable. When **Research Report** is selected, enable the dropdown with **Text (.txt)**, **HTML (.html)** and **LaTeX (.tex)**; default Text. (Markdown is intentionally not offered.)
- Display an **editable filename stem** initialized safely from the project name. Keep the extension separate and automatically determined: **.json** for Project Audit, and **.txt / .html / .tex** for the selected Research Report format. Switching export type or report format must **preserve the user's edited stem** and change only the extension. Validate/sanitize unsafe filename characters and empty stems, and never allow a manually entered extension to override the selected format. Ensure the filename control uses available dialog width so the stem is not awkwardly truncated; keep the extension fully visible beside it. The input and extension must remain usable at narrow viewport widths.
- Provide an **Open in browser tab** checkbox (not a radio button), default unchecked. The dialog header contains the title only, with **no Create/Download action at the top**. Place the primary **Download** button and **Cancel** at the bottom of the dialog, using the standard dialog button styling.
- Research Report is generated deterministically from saved data, with no model calls or billing. Include project title/problem, strategies/approaches, sessions in durable order, execution status distinct from outcome, outcomes/caveats, artifacts' claims/methods/assumptions/evidence status, objections, decisions and open obligations. Preserve chronology and explicitly distinguish provisional/unverified findings. Gracefully handle empty projects, legacy records and missing optional fields.
- Generate usable escaped UTF-8 text, standalone safe HTML (no model-output script injection), and compilable escaped LaTeX. Preserve mathematical notation where feasible; test injection and special-character handling.
- Create downloads the chosen audit or report using the derived filename. If the checkbox is checked, also open a viewable representation in a new browser tab; avoid popup blockers by opening during the initiating gesture and handle blocked tabs gracefully. Verify JSON/text/HTML/LaTeX behavior in a real browser. Handle object URL cleanup.
- Keep modal visuals consistent with existing SIGMA dialogs, including narrow screens, Escape, focus management, Cancel, and error recovery.

## Strategy assessments and strategy enable/disable

- Hide the strategy drag/reorder thumb when the project has only one strategy, since reordering is not meaningful. Show it when there are at least two strategies and retain existing drag behavior and accessible labeling.

- In each session's expanded details, show a compact **Strategy Assessments** table listing **all project strategies in the same order as the Strategies list**, mapping each strategy to its assessment for this session. Use the exact theme term **Assessment** (not “evaluation” or “rating”). Include the strategy title and a concise assessment label, with a brief rationale when available. Make it clear this is the assessment for that strategy's contribution in this session, not the overall session outcome. For any strategy that was disabled and therefore not used, the Assessment cell must say **Disabled**. If a strategy was eligible but not used, or no assessment was produced for another reason, distinguish that state explicitly rather than implying a negative assessment. Handle long strategy names and narrow layouts without breaking the session details.
- Keep execution status, session outcome, and strategy assessment distinct. A completed session can have a positive outcome while one or more strategies are assessed as unproductive for the project's objective. Assessments must be grounded in recorded evidence and the project's stated objective; do not infer “not productive” solely because no next step remains.
- In the Strategies list, add an underlined **Disable** / **Enable** action immediately to the left of **Fork**. Preserve the existing title-row action styling and hover descriptions. Disabled strategies remain visible and may still be edited, forked, or removed.
- Disabled strategies must not be selectable for starting a session or otherwise launched by Play/Start flows. Enforce this in both UI and backend/API validation, not just by hiding a control. If a currently selected strategy becomes disabled, prevent starting a session and explain why.
- Show an unobtrusive, clear disabled state on the strategy row. Enabling restores eligibility for new sessions without changing the strategy content or its existing session history. Disabling a strategy must not silently stop or mutate sessions already running from it. Each session's Strategy Assessments table must reflect the strategy's eligibility/use for that session, not merely its current enabled/disabled state; toggling a strategy later must not rewrite historical session assessments.
- Persist the enabled/disabled state across reloads and restarts, with safe defaults for existing project data (legacy strategies default to enabled). Add regression coverage for persistence, action placement/order, disabled-strategy session rejection through direct API calls, and edit/fork/remove remaining available while disabled.
