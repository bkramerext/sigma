# Blue's permanent iteration protocol

Human instruction dated 2026-10-24. Applies to Blue on `blue_session` for every
future iteration. The latest human instruction takes precedence over older
mailbox guidance, including the earlier read-only-only polling rule.

1. Synchronize safely, read the coordinator's entire applicable outgoing message
   and any standing supplement, and complete the assigned scope. Do not advance
   into another increment merely because a supplemental mailbox number exists.
2. Validate with appropriate focused/full tests and real browser exercise of
   applicable research features. No paid or live provider work without separate
   explicit authorization. Preserve fixture/historical/live distinctions.
3. Use SIGMA's own export paths to retain actual exercised projects, strategies,
   sessions, Outcomes, evidence and relevant reports under
   `docs/evaluations/increment_N/exports/`. Preserve exported bytes. Manifest the
   source project/session IDs, capture/app and publishing commits, actual activity,
   omissions and unsupported formats; never fabricate sessions or Markdown output.
4. Fetch and safely reconcile the remote branch, commit/push all implementation,
   tests/evidence/exports, then commit/push the immutable `messages/blue_in_N.md`
   response. Keep outgoing and earlier incoming messages unchanged. No self-merge,
   competing PR, force-push, reset or discarded local work.
5. Only when the iteration is reported and the working tree is clean, poll every
   **30 seconds**: fetch and pull `blue_session` with **fast-forward-only** updates,
   check the next expected coordinator message, and keep waiting while absent.
   Use an actual active polling process; do not claim background polling after
   exiting. Waiting is not a reason to terminate or request human relay.
6. When the next applicable outgoing message arrives, stop polling immediately,
   read it completely, and execute the next iteration. After validation, exports
   and reporting, return to the polling phase. Repeat indefinitely until the human
   changes or stops this instruction.

A dirty tree, failed fetch or failed fast-forward synchronization stops polling
for investigation. Preserve local work and report the concrete failure; never
force synchronization. The currently expected message after Increment 2 is
`blue_out_4.md`; `blue_out_3.md` is a standing export supplement to Increment 2,
not a separate implementation increment. The next implementation increment is 3
only when the coordinator names its scope.

Do not coordinate or communicate directly with other Codex workers. Report
dependencies, conflicts, and requests for other workers to your ChatGPT coordinator
through the human.
